01_ Ingreso punto de entrada & seguridad
→entry_point

API Backend

Puerta de entrada del sistema

Expone la API que actúa como único punto de entrada: recibe las solicitudes del cliente y dispara la ejecución de todo el flujo del sistema.

[ ! ]security

Guardrails Service

Seguridad & control de scope

Analiza cada solicitud entrante antes de levantar el resto de la infraestructura. El agente opera con un scope definido: no responde consultas fuera de dominio y resiste prompt injections y otros vectores de ataque.

04_ Estado & memoria continuidad de largo plazo
◈long_term

Memory Service

Memoria de largo plazo del proyecto

Almacena los artefactos propios de cada proyecto de migración: estado actual, antecedentes del servicio a migrar y aprendizajes acumulados entre sesiones.

≡session

Session Service

Historial de sesión

Persiste la conversación con el agente: memoria de corto plazo que da continuidad al trabajo dentro de cada sesión.

¿Por qué memoria de largo plazo?

Las migraciones son proyectos de largo plazo: pueden requerir múltiples sesiones o quedar a mitad de camino. Con memoria persistente, el agente retoma el trabajo sabiendo el estado exacto del proyecto, los antecedentes del servicio y todo lo ya descubierto.

↓
05_ Ejecución código en entorno aislado
▶sandbox

Codesandbox Gateway

Ejecución segura de código

Gateway hacia codesandboxes aisladas, donde el agente ejecuta y prueba código de forma segura: sondea el servicio original, valida hipótesis y verifica que el reemplazo responda exactamente igual.

Nota de implementación

El diseño objetivo del sistema es de microservicios. Como punto de partida —y dado el tiempo delimitado de la hackathon— se implementa como un monolito modular, preservando los límites entre módulos para poder extraer servicios cuando el momento lo requiera.
